## 5. Table 2 overfull box (diagnosis only — no change made)

* The Status-column overfull box is **243.25388 pt**, measured identically in an isolated build of the
  committed `tab03_anchor_errors.tex` and in the full document — so it is content-caused, not float-induced.
* Cause is **two-fold**, not the P12AF labels alone:
  1. **Pre-existing**: the fixed-column `tabular` (`lp{3.2cm}p{2.8cm}cccp{2.5cm}c`) already overflowed by
     **173.24463 pt** before P12AF (measured on a build whose only difference is the pre-P12AF
     `sec05`/`tab03` text: same 613 overfull boxes, same page count −1 for the text difference);
  2. **P12AF**: the mandated longer status identifiers add **+70.01 pt** (173.24 → 243.25 pt).
* **Substantive consequence (disclosed, not fixed):** in the rendered PDF the overflow pushes the
  final `Status` column **entirely off the printed page** — the table shows `GRAPHICAL_VALIDATION / PASS`,
  `NOT VALIDATED` and `PASS` only as clipped slivers at the right edge of page 16. The Table-2 *content*
  is therefore not readable as typeset, although it is correct in the source and in Table 5's restatement.
* **No cosmetic change was made.** Making it readable requires a layout-only change (e.g. `c` → `p{1.9cm}`
  for the status column and re-sizing the neighbouring `p{}` columns), which is **outside a build repair**
  and is reported here as an optional cosmetic correction requiring authorisation. The same applies to the
  other large pre-existing boxes (Table 4 782.05 pt, Table 7 251.57 pt, Table 1 214.16 pt).
